# Стек, команда и роль ИИ v0.1

## Почему воксели (решение уже принято)

1. **Проще для ИИ-разработки**: воксельные миры легче генерировать процедурно —
   terrain, биомы, структуры собираются из блоков, нет сложных мешей/анимаций скелета.
2. **Читаемость** — «говорящий визуал»: воксельный силуэт врага читается лучше,
   чем в текстурированном шуме. Телеграфы атак видны чётко.
3. **Аудитория**: Roblox доказал, что воксели = массовость.
4. **Стиль**: Cube World — яркий, наш — тёмный. Эстетика задаётся палитрой,
   светом и тоном, а не разрешением.

## Движок: кандидаты

| Движок | Плюсы | Минусы |
|---|---|---|
| **Godot 4** | Бесплатный, лёгкий, GDScript/C#, воксельные аддоны есть | Меньше готовых воксельных решений |
| **Unity** | Voxel Tools, огромный ассет-стор, комьюнити | Лицензия (Runtime Fee), тяжелее |
| **Unreal 5** | Voxel Plugin (бесплатный, мощный), мега-скейл миров | Тяжёлый для соло-дева, кривая обучения |
| **Minetest-форк** | Готовый воксельный движок, сеть, моды на Lua | Ограниченный геймплейный потенциал, меньше контроля |
| **Свой на WebGPU/JS** | Полный контроль | Это ещё один проект внутри проекта |

**Пока не решено — нужен прототип**: выбор движка зависит от того, как быстро
заработает ядро боя (тайминги, телеграфы, хитбоксы).

## Кто понадобится (помимо тебя и ИИ)

| Роль | Критичность | Может ли ИИ закрыть? |
|---|---|---|
| **Программист геймплея** (бой, движение, камера) | 🔴 Критично | Частично: ИИ пишет код, но отладка фи-ла боя = человек |
| **Художник по анимациям/таймингам** (читаемость атак) | 🔴 Критично | Нет: это чувство ритма, его нельзя сгенерировать |
| **Воксель-художник** (модели, палитры, стиль) | 🟡 Важно | ИИ генерит ассеты, но арт-дирекция — человек |
| **Левел-дизайнер** (биомы, точки интереса, «говорящий визуал») | 🟡 Важно | ИИ помогает генерить, сеттинг-логика — человек |
| **Саунд-дизайнер** (музыка, звуки боя) | 🟡 Важно | ИИ генерит (Suno/ы), но друг-звукореж — лучше |
| **Геймдизайнер баланса** (формулы, кривые) | 🟡 Важно | ИИ-симуляции сильно помогают |
| **QA/тестировщик** (тайминги, фидбек аудитории 13-14) | 🟡 Важно | ИИ-боты частично, живое тестирование — люди |

**Вывод**: соло + ИИ реально, но **якорная точка — чувство боя** (тайминги,
читаемость). Если она будет хороша — остальное достроится.

## Где ИИ помогает максимально

### Код
- Процедурная генерация мира (terrain, биомы, структуры) — ИИ пишет 80% кода.
- ИИ противников: поведенческие деревья, телеграфы, паттерны — ИИ-ассистировано.
- Инструменты: OpenCode, Claude, Cursor + ревью человеком.

### Контент
- Воксельные модели: генерация примитивов, раскраска, палитры.
- Тексты: диалоги NPC, лор, описания предметов — LLM с редактурой.
- Звуки боя: синтез SFX, вокалы, эмбиент — до прихода друга-звукорежа.
- Музыка: Suno/ы как черновик, финал — звукорежиссёр.

### Баланс и тесты
- Симуляции боя: прогон формулы урона, DPS, тайминги — Python/Monte Carlo.
- ИИ-боты для QA: автопрогон сценариев (волк атакует, игрок уклоняется).
- А/B тесты паттернов: какой телеграф читается лучше.

### Управление проектом
- GDD, документы, спринты, задачи — Hermes/агенты ведут.
- Техдолг, CI/CD, ветки — автоматизация.

## Прототип: что проверяем первым

1. **Ядро боя**: телеграф → реакция → контратака. Ощущается честно?
2. **Воксельная читаемость**: видно ли замах врага на кубической модели?
3. **Генерация мира**: Луга + болотца, «говорящий визуал» опасности.
4. **Формула урона**: `max(1, ATK − DEF)` — весело или уныло?
